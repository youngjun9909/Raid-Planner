# 로스트아크 레이드 공대 자동 편성 도구 설계

## 의도와 이유

친구 약 5명이 각자 여러 캐릭터(원정대)를 갖고 있고, 매주 레이드 공대를 사람이 직접 계산해서 짠다.
지금은 캐릭터별 레벨·전투력의 평균을 맞춰 가며 짜는데, 공대를 짜는 도중에 친구가 "그 레이드는 이미 갔다"고
말해 주는 방식이라 그때마다 처음부터 다시 짜야 한다. 이 번거로움을 없애는 것이 목적이다.

핵심 가치: **캐릭터별 클리어 상태를 반영해, 레이드마다 현실적인 공대 후보를 즉시 다시 계산해 보여 준다.**

## 사용자와 환경

- 사용자: 친구 5명 내외 (사이트/봇 규모는 소규모, 동시 사용 거의 없음).
- 개발자(요청자)는 디스코드 봇과 Vercel을 처음 다룬다. 계정 생성과 설정은 단계별로 안내해야 한다.
- 언어/프레임워크는 빌더에게 맡긴다 (아래 "빌더에게 맡기는 것" 참고).

## 목표

1. 친구가 대표 캐릭터 이름만 등록하면 로스트아크 Open API로 원정대 캐릭터(이름, 직업, 아이템 레벨, 전투력)를 가져온다.
2. 선택한 레이드마다 공대 후보를 자동으로 계산해 보여 준다.
3. 캐릭터×레이드 단위로 "이번 주 클리어함"을 표시하면 해당 캐릭터만 후보에서 빠지고 공대를 즉시 다시 계산한다.
4. 주간 초기화(수요일 06:00 KST)에 클리어 표시를 모두 지운다.
5. **웹페이지와 디스코드 봇 둘 다** 제공한다. 둘은 같은 데이터와 같은 편성 로직을 쓴다.
6. 추천 순서: 편성 로직 + 웹을 먼저 만들어 결과를 눈으로 검증하고, 그다음 디스코드 봇을 붙인다.

## 비목표 / 안티목표

- 비목표: 일반 채팅 읽기, 모르는 사람(외부인) 모집·매칭, 골드 계산 최적화, 레이드 공략/딜량 판정.
- 안티목표 (이러면 실패): 입장 레벨이 안 되는 캐릭터를 공대에 넣음 / 같은 사람의 캐릭터가 한 공대에 둘 이상 들어감 /
  이미 클리어한 캐릭터를 다시 추천함 / 단 하나의 정답만 강요하고 후보를 보여 주지 않음.

## 편성 규칙

### 인원과 역할
- 4인 레이드는 서포터 1명, 8인 레이드는 서포터 2명이 필요하다 (4명당 서포터 1명).
- 친구 중 서포터가 부족한 경우가 많다. 이때 서포터 자리를 비워 두고 "외부 서포터 N명 필요"라고 표시한다.
- 외부인으로 채우는 자리(서포터/딜러 구분)를 결과에 명시한다. 외부인의 전투력은 모르므로 평균 계산에서는 제외한다 (이 처리는 설계자의 선택).

### 제약
- **입장 레벨은 엄격한 조건.** 레이드 입장 레벨에 못 미치는 캐릭터는 그 레이드 후보에서 제외한다.
- **한 사람당 한 공대에 캐릭터 하나만.** 같은 사람의 다른 캐릭터를 다른 레이드에 쓰는 것은 괜찮다 (공대는 레이드마다 따로 짠다).
- **클리어한 캐릭터는 해당 레이드에서 제외.** 캐릭터×레이드 단위로 판단한다 (사람 단위가 아님).

### 목표 기준
- 레이드마다 공대를 따로 짠다.
- 이번 주에 어떤 레이드를 돌지는 매번 사용자가 고른다. 하나도 안 도는 주도 있다 (유동적).
- 권장 전투력은 **부드러운 기준.** 낮아도 갈 수 있다. 공대 한 명이 아니라 **공대 전체 평균 전투력**을 권장 범위와 비교한다.
- 공대가 둘 이상일 때(예: 4인 레이드에 5명)는 공대끼리 평균 전투력이 비슷하게 나오도록 분배한다.
- 평균이 높을수록 무조건 좋은 것이 아니라, 요구 수준에 알맞고 공대 간 균형이 맞는 조합이 좋다.

### 후보 제시
- 정답 하나가 아니라 **여러 후보를 보여 주고 친구들이 고른다.** 예: 5명이 4인 레이드를 갈 때 "3+2" 분배와 "4+1" 분배를 각각 계산.
- 후보마다 공대별 평균 전투력, 권장 대비 단계(여유/빠듯함/위험), 서포터 배치, 필요한 외부인 수를 보여 준다.
- 권장 대비 단계의 구체적 경계값은 빌더가 제안하고 사용자가 조정할 수 있게 설정으로 둔다.
- 평균 전투력 계산 시 서포터는 제외하고 딜러만 계산하는 방식을 참고안으로 둔다 (loasync 기준표의 1인분 계산 방식: 4인 3명, 8인 6명). 최종 방식은 빌더가 제안한다.

## 데이터와 외부 API

- 로스트아크 공식 Open API (https://developer-lostark.game.onstove.com): 캐릭터/원정대/장비 정보 조회. 인증은 헤더 `authorization: bearer <JWT>`,
  분당 100회 제한(429 응답), 응답 헤더 `X-RateLimit-*`로 잔여량 확인. 토큰은 서버에만 보관한다.
- 확인하지 못한 것 (빌더가 실제 호출로 검증해야 함):
  - 원정대 캐릭터 목록 조회에서 아이템 레벨, 직업, 전투력을 어디까지 얻을 수 있는지 (전투력은 별도 상세 조회가 필요할 수 있음).
  - 서포터 직업 판별 기준 (직업명/직업 각인으로 판단해야 할 수 있음).
  - 주간 레이드 클리어 여부를 API가 제공하는지. 제공하지 않는다면 클리어 표시는 수동 입력이다 (가정은 수동).
- 캐릭터 정보는 매번 호출하지 않고 저장해 두고 갱신 버튼/주기 갱신으로 처리해 호출 제한을 지킨다.

## 구성과 배포

- 웹과 디스코드 봇은 하나의 서버리스 앱(Vercel 예정)에서 같은 편성 로직과 같은 저장소를 공유한다.
- 디스코드 봇은 상시 접속(게이트웨이) 방식이 아니라 **Interactions Endpoint URL(HTTP 웹훅)** 방식으로 한다:
  슬래시 명령어와 버튼/메뉴 클릭을 요청으로 받는다. 서명 검증이 필요하고, 3초 안에 응답하거나 먼저 "처리 중"으로 응답한 뒤 결과를 보낸다.
- 저장소는 Vercel에서 파일을 못 쓰므로 외부 DB(예: Upstash Redis 또는 Supabase 무료 플랜 등)를 쓴다. 선택은 빌더에게 맡긴다.
- 주간 초기화는 수요일 06:00 KST에 정기 작업(Vercel Cron 등)으로 클리어 표시를 지운다.

## 화면/상호작용

### 웹
- 친구 선택 후 캐릭터 목록 표, 레이드별 체크 칸으로 "이번 주 클리어함" 표시. 한눈에 5명 전체를 본다.
- 이번 주 돌 레이드를 고르면 공대 후보(분배 방식별)를 보여 준다. 표시를 바꾸면 즉시 다시 계산한다.
- 실시간 동기화까지는 필요 없다 (새로고침이면 충분, 이는 설계자의 선택).

### 디스코드
- 슬래시 명령어 예: 등록, 공대(레이드 선택), 클리어(내 캐릭터 표시), 현황(전체 현황 텍스트 표), 명령어(도움말).
- `/`만 입력하면 디스코드가 등록된 명령어 목록을 설명과 함께 자동으로 보여 준다. 그러려면 모든 명령어에 짧은 한글 설명을 붙여 등록한다.
- `/명령어`를 실행하면 사용 가능한 명령어와 사용 방법을 한 번에 정리해서 보여 준다 (본인에게만 보이는 메시지로).
- 클리어 표시는 완전한 체크박스가 없으므로 토글 버튼(☐/☑, 한 메시지 최대 25개)이나 다중 선택 메뉴로 한다.
  디스코드에 입력창 안에서 쓰는 체크박스형 컴포넌트가 새로 생겼다는 정보가 있으나 확인되지 않았다. 빌더가 쓸 수 있는지 확인한다.
- 사람별 메시지로 나누어 25개 제한을 피한다.

## 권한과 신뢰

- 친구들끼리 쓰는 소규모 도구다. 누가 누구의 클리어를 표시할 수 있는지에 대한 엄격한 권한은 요구하지 않는다 (이는 설계자의 가정이며 빌더가 단순한 방식을 제안한다).
- 로스트아크 API 토큰과 디스코드 봇 토큰은 서버 환경변수로만 보관하고 코드/저장소에 넣지 않는다.

## 빌더에게 맡기는 것

- 언어, 프레임워크, DB 선택.
- 공대 분배 알고리즘 (후보 수가 작아 완전 탐색/휴리스틱 모두 가능), 전투력 평균 계산의 세부 방식.
- 권장 대비 단계(여유/빠듯함/위험)의 경계값 제안.
- UI 세부 디자인.
- 디스코드 앱 생성과 Vercel 배포를 처음 쓰는 사용자에게 단계별로 안내하는 방법.

## 설계자의 판단 (빌더 검토 반영, 사용자가 확인할 부분)

- **외부인 처리:** 공대는 레이드 인원(4 또는 8)을 모두 채운 것으로 보고, 친구로 못 채우는 자리는 외부인 자리로 표시한다.
  후보는 분배 방식별로 보여 주고(예: 5명이 4인 레이드면 3+2, 4+1), 후보마다 필요한 외부인 수를 함께 보여 준다. 외부인 최소화를 기본 정렬 기준으로 한다.
- **서포터 배치:** 공대의 서포터 자리는 서포터 캐릭터만 들어간다. 서포터가 남아도 딜러 자리에는 기본으로 넣지 않는다 (필요하면 빌더가 옵션으로 제안).
  평균 전투력은 딜러만 계산하는 방식을 기본으로 한다.
- **후보에 캐릭터 선택 포함:** 후보는 분배 방식뿐 아니라 "그 사람의 어느 캐릭터를 쓰는가"까지 달라진다. 결과는 상위 몇 개(빌더가 정함)만 보여 준다.
- **여러 레이드:** 같은 캐릭터를 다른 레이드에 쓰는 것은 허용한다. 레이드끼리 서로 조율하지 않고 각각 독립으로 계산한다.
  주간 골드 제한(캐릭터당 레이드 수, 원정대당 골드 캐릭터 수)은 편성에 반영하지 않는다.
- **사용자 모델:** 웹은 로그인 없이 친구를 목록에서 고르고, 공유 비밀번호 정도의 최소 보호만 둔다. 디스코드는 등록 명령을 쓴 디스코드 계정을 그 친구로 연결한다.
- **전투력 대체 경로:** API로 전투력을 못 얻으면 수동 입력을 허용한다. 첫 구현 단계에서 API로 실제 얻을 수 있는 값을 먼저 검증한다.

## 난이도와 클리어 단위 (사용자 확인)

- 한 캐릭터는 같은 레이드에서 한 주에 **하나의 난이도만** 갈 수 있다. 클리어 표시는 "캐릭터 × 레이드 이름" 단위이고, 난이도는 그 안에서 고른 값이다.
  (예: 세르카 노말을 클리어하면 같은 주에 세르카 하드·나이트메어는 못 간다.)
- 편성할 때 레이드를 고르면 난이도도 함께 고른다. 같은 레이드의 다른 난이도 공대를 동시에 편성해 볼 수는 있지만, 한 캐릭터는 그중 한 난이도에만 쓸 수 있다.
- 지평의 성당의 1·2·3단계도 난이도와 같게 취급한다 (사용자 확인함).
- 클리어한 캐릭터는 클리어한 난이도로 이미 갔다고 기록하고, 다른 난이도에서도 제외한다.

## 성공 기준

- 친구 5명의 원정대를 불러와 임의의 레이드를 골랐을 때, 레벨 제한/서포터 규칙/한 사람 한 캐릭터 규칙을 지키는 후보를 즉시 보여 준다.
- 한 캐릭터의 클리어를 표시하면 그 캐릭터만 빠진 채 후보가 다시 계산된다.
- 같은 결과를 웹과 디스코드에서 모두 볼 수 있다.
