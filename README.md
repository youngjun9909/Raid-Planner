# 로아 레이드 공대 짜기

## 무엇을 하는 도구인가요

친구들의 로스트아크 원정대를 한 번 등록해 두면, 레이드를 고를 때 **이번 주에 아직 안 간 캐릭터**로 공대 후보를 자동으로 짜 줘요. 웹 화면과 디스코드 슬래시 명령어(`/공대` 등)로 모두 쓸 수 있고, 클리어 기록은 매주 수요일 06:00(KST)에 새로 시작해요. 친구 5명 안팎이 쓰는 것을 기준으로 만들었어요.

## 준비물

- 로스트아크를 하는 계정 (Stove 로그인)
- 디스코드 계정과, 봇을 초대할 수 있는 서버(관리 권한)
- GitHub 계정 (Vercel에 코드를 올리는 데 편해요)
- 무료로 가입할 수 있는 서비스: Vercel, Upstash
- PC에 Node.js (로컬 실행/명령어 등록용)

> 메뉴 이름이나 화면 배치는 각 서비스가 바꿀 수 있어요. 아래 설명과 조금 다르면 비슷한 이름의 메뉴를 찾아보세요.

## 1. 로스트아크 API 토큰 발급

1. <https://developer-lostark.game.onstove.com> 에 접속해 Stove 계정으로 로그인해요.
2. 클라이언트(API 사용 신청)를 새로 만들어요. 이름과 용도는 자유롭게 적어도 돼요.
3. 만들어지면 긴 문자열(JWT)이 나와요. 이것을 복사해 두세요. 이것이 `LOSTARK_JWT` 예요.

참고: 요청할 때는 `authorization: bearer <JWT>` 헤더를 쓰고(이 앱이 알아서 해요), 토큰은 삭제하지 않는 한 만료되지 않아요. 남에게 보여 주면 안 돼요.

## 2. 디스코드 앱 만들기

1. <https://discord.com/developers/applications> 에서 **New Application**을 눌러 이름을 정해요.
2. **General Information** 화면에서 두 값을 복사해 둬요.
   - **Application ID** → `DISCORD_APP_ID`
   - **Public Key** → `DISCORD_PUBLIC_KEY`
3. 왼쪽 **Bot** 탭에서 **Reset Token**을 눌러 나온 토큰을 복사해요 → `DISCORD_BOT_TOKEN`. 이 토큰은 다시 볼 수 없으니 바로 저장하세요.
4. 서버에 초대하기: **OAuth2** → **URL Generator**에서 스코프를 고르고, 아래에 만들어진 URL을 브라우저에 붙여 넣어 서버를 선택해요.
   - `applications.commands` : **필수**. 서버에서 슬래시 명령어를 쓰려면 필요해요.
   - `bot` : 선택. 이 앱은 디스코드에 접속해 있는 방식이 아니라, 명령어가 쓰일 때 디스코드가 우리 주소로 요청을 보내 주는 방식이라 없어도 동작해요. 멤버 목록에 봇이 보이길 원할 때만 추가하세요(권한은 필요 없어요).

## 3. Upstash Redis 만들기

데이터(친구, 클리어 기록)를 저장할 곳이에요. Vercel 서버는 요청마다 꺼졌다 켜져서 파일에 저장할 수 없어요.

1. <https://upstash.com> 에 가입하고 Redis 데이터베이스를 새로 만들어요.
2. 리전(지역)은 Vercel 함수가 도는 리전과 같은 곳을 고르세요. Vercel 함수의 기본 리전은 미국 동부(`iad1`, 워싱턴 D.C.)라서 따로 바꾸지 않았다면 Upstash도 **US East (N. Virginia, us-east-1)** 를 고르는 것이 가장 빨라요. Vercel의 **Settings → Functions → Function Region**을 바꿨다면 그와 가까운 리전을 고르세요.
3. 만든 데이터베이스 화면의 **REST API** 부분에서 두 값을 복사해요.
   - REST URL → `UPSTASH_REDIS_REST_URL`
   - REST TOKEN → `UPSTASH_REDIS_REST_TOKEN`

Vercel의 **Storage / Marketplace** 메뉴에서 Upstash를 연결하면 이름이 `KV_REST_API_URL` / `KV_REST_API_TOKEN` 으로 자동으로 들어가기도 해요. 이 앱은 두 이름을 모두 알아들어요(`UPSTASH_REDIS_REST_*` 가 있으면 그것을 먼저 써요). URL과 토큰은 같은 쌍에서 와야 해요.

배포 환경(Vercel)에서 둘 다 없으면 앱이 데이터를 잃지 않도록 **저장소를 쓰는 모든 요청을 거부하고** "저장소(Upstash Redis) 환경변수가 설정되지 않았어요…" 안내를 보여 줘요. 이 안내가 보이면 환경변수를 넣고 다시 배포하세요.

## 4. Vercel 배포

1. 이 폴더를 GitHub 저장소로 올려요 (또는 `npm i -g vercel` 후 `vercel` 명령으로 바로 배포해도 돼요).
2. <https://vercel.com> 에서 **Add New → Project**로 그 저장소를 가져와요(Import). Next.js는 자동으로 인식돼요.
3. 배포 전에 **Environment Variables**에 아래 값을 넣어요.

| 이름 | 필수 | 용도 |
| --- | --- | --- |
| `LOSTARK_JWT` | 필수 | 1번에서 받은 로스트아크 API 토큰 |
| `DISCORD_PUBLIC_KEY` | 디스코드 사용 시 필수 | 디스코드 요청의 서명을 확인해요. 없으면 모든 디스코드 요청을 거부해요 |
| `DISCORD_APP_ID` | 명령어 등록 시 필수 | 디스코드 앱 ID (명령어 등록 스크립트가 써요) |
| `DISCORD_BOT_TOKEN` | 명령어 등록 시 필수 | 봇 토큰 (명령어 등록 스크립트가 써요) |
| `UPSTASH_REDIS_REST_URL` | 필수 | 저장소 주소 (또는 `KV_REST_API_URL`). 배포 환경에서 없으면 저장소를 쓰는 요청이 503 안내로 거부돼요 |
| `UPSTASH_REDIS_REST_TOKEN` | 필수 | 저장소 토큰 (또는 `KV_REST_API_TOKEN`) |
| `APP_PASSWORD` | **필수** | 웹 화면 비밀번호. 배포 환경에서 비우면 모든 웹 API가 "APP_PASSWORD를 설정해 주세요"(503)로 거부돼요. 로컬 개발에서만 비워 둘 수 있어요 |
| `CRON_SECRET` | 필수 | 주간 자동 작업 인증. 비우면 크론이 거부돼요 |
| `WEB_URL` | 선택 | 디스코드 `/웹` 버튼이 여는 웹 주소(`https://…`). 보통은 필요 없고, 사이트 주소가 바뀌었을 때만 설정하세요 |

`APP_PASSWORD`는 친구들과 공유할 비밀번호예요. 이 앱은 비밀번호 시도 횟수를 제한하지 않아요(rate limiting 없음). 주소가 알려지면 짧은 비밀번호는 여러 번 시도해서 맞힐 수 있으니, 외우기 쉽되 너무 짧지 않게(예: 단어 3~4개를 이은 문장) 정하고 주소를 공개된 곳에 올리지 마세요. `CRON_SECRET`은 추측할 수 없는 긴 문자열이어야 해요. PC 터미널에서 이렇게 만들 수 있어요.

```
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

4. **Deploy**를 눌러요. 끝나면 `https://<프로젝트>.vercel.app` 같은 주소가 생겨요.

이 저장소의 `vercel.json`이 매주 수요일 06:00(KST) = 화요일 21:00(UTC)에 `/api/cron/weekly`를 부르도록 설정해 둬요. 이 작업은 지난주 클리어 기록을 지우고 친구들의 원정대 정보를 새로 불러와요(수동 입력한 전투력과 디스코드 연결은 유지돼요). Vercel은 `CRON_SECRET`이 있으면 자동으로 인증 헤더를 붙여 줘요.

주간 작업은 친구 수 x 캐릭터 수만큼 로스트아크 API를 부르므로 오래 걸릴 수 있어서 최대 실행 시간을 300초로 잡아 뒀어요(`maxDuration = 300`). Vercel 무료(Hobby) 플랜은 **Fluid compute**가 켜져 있을 때 300초까지 허용해요(새 프로젝트는 기본으로 켜져 있어요. **Settings → Functions**에서 확인). Fluid compute가 꺼져 있으면 더 낮은 한도가 적용돼 친구가 많을 때 중간에 끊길 수 있어요. 끊기더라도 매주 갱신을 시작하는 친구를 바꿔 가며 돌기 때문에 같은 친구만 계속 빠지지는 않아요. 입장 레벨(가장 낮은 레이드 기준)에 못 미치는 캐릭터는 전투력을 조회하지 않아 요청 수도 줄여요.

## 5. 디스코드에 주소 연결

1. 디스코드 개발자 포털 → 내 앱 → **General Information**의 **Interactions Endpoint URL**에 `https://<도메인>/api/discord` 를 넣고 저장해요.
2. 저장하는 순간 디스코드가 확인용 PING을 보내요. 우리 서버가 서명을 확인하고 응답하면 저장이 성공해요.
3. 실패하면:
   - Vercel 환경변수에 `DISCORD_PUBLIC_KEY`가 정확히 들어갔는지(복사할 때 공백이 섞이지 않았는지) 확인해요.
   - 환경변수를 추가/수정했다면 Vercel에서 **다시 배포(Redeploy)** 해야 적용돼요.
   - 주소 끝에 `/api/discord`를 정확히 썼는지 확인해요.

## 6. 명령어 등록

PC에서 한 번만 하면 돼요(명령어 목록을 바꿨을 때 다시 실행). 프로젝트 폴더에 `.env.local` 파일을 만들고(`.env.example`을 복사하세요) `DISCORD_APP_ID`와 `DISCORD_BOT_TOKEN`을 채운 뒤:

```
npm install
npm run register-commands
```

`등록 성공`이 나오면 디스코드에서 `/`를 눌렀을 때 명령어가 보여요. 전체 반영에 잠시 걸릴 수 있어요.

## 7. 첫 사용

**웹**: 배포 주소를 열고 `APP_PASSWORD`를 입력해요. 친구를 추가할 때 표시 이름과 대표 캐릭터 이름을 넣으면 원정대가 자동으로 불러와져요. 같은 캐릭터를 두 친구로 등록할 수는 없어요("이미 등록된 캐릭터예요"). 잘못 등록한 친구는 원정대 목록의 **삭제** 버튼으로 지울 수 있어요(한 번 더 확인해요. 그 친구의 이번 주 클리어 기록도 함께 지워져요).

**디스코드**: 각자 아래 명령어를 써요.

- `/명령어` : 사용법 보기
- `/등록 대표캐릭터:<이름>` : 내 원정대 등록/갱신
- `/공대 레이드:<레이드>` : 이번 주 안 간 캐릭터로 공대 후보 짜기
- `/클리어` : 내 캐릭터의 이번 주 클리어 표시
- `/현황` : 이번 주 전체 클리어 현황
- `/웹` : 웹 화면으로 가는 링크 버튼
- `/숙련도 캐릭터:<내 캐릭터> 레이드:<레이드> 숙련도:<숙련|반숙|클경>` : 내 캐릭터의 레이드별 숙련도 정하기 (캐릭터 칸에 글자를 넣으면 내 캐릭터 목록이 떠요. 결과는 나에게만 보여요)

- `/난이도 캐릭터:<내 캐릭터> 레이드:<레이드 이름> 난이도:<자동|난이도|안 감>` : 내 캐릭터가 그 레이드를 어떤 난이도로 가는지 정하기 (아래 "가는 난이도" 참고. 캐릭터 칸에 글자를 넣으면 내 캐릭터 목록이 떠요. 결과는 나에게만 보여요)

처음에는 `/명령어` → `/등록` → `/공대` → `/클리어` 순서로 눌러 보며 응답이 오는지 확인하세요. 웹에서도 같은 친구가 보이면 성공이에요.

> **업데이트 후 꼭 할 일**: `/숙련도`, `/난이도`처럼 새 명령어가 추가된 버전을 배포했다면 PC에서 `npm run register-commands`를 **한 번 더** 실행해야 디스코드에 새 명령어가 보여요 (6번 참고). 이미 있는 명령어에 선택지나 설명이 바뀐 경우에도 다시 실행하세요.

### 가는 난이도 (자동 · 직접 정하기 · 안 감)

캐릭터마다, **레이드 이름마다** "어떤 난이도로 가는지"를 정해요. 아이템 레벨 1720인 캐릭터를 카제로스 4막 **노말**로 추천하면 이상하니까, 그 캐릭터가 가는 난이도의 추천에만 넣어요.

- **자동** (기본값): 레벨로 갈 수 있는 **가장 높은 난이도**예요. 예를 들어 1720이면 4막은 하드, 1705면 4막은 노말, 지평의 성당 1735면 2단계예요. 대부분은 아무것도 안 해도 돼요.
- **직접 정하기**: 하드 대신 노말로 가는 캐릭터처럼 예외만 정하세요. 바꾸면 **그 레이드의 다른 난이도 추천에서는 그 캐릭터가 빠져요** (노말로 정하면 하드 추천에는 안 나와요).
- **안 감**: 그 레이드는 아예 안 가요. 어느 난이도 추천에도 안 나와요.
- 레벨보다 높은 난이도를 정해 두면 저장은 되지만, 입장 레벨이 될 때까지는 추천에 안 나와요.

정하는 곳: 웹의 캐릭터 카드(레이드 칩 옆 ⋯ 설정) 또는 디스코드 `/난이도`. `/클리어` 메뉴와 웹 칩에는 그 캐릭터가 가는 난이도가 보여요. 원정대를 갱신하거나 주간 초기화가 지나도 그대로 남아요.

### 1700 미만 캐릭터는 안 보여요

가장 낮은 레이드 입장 레벨(1700) 미만 캐릭터는 웹 화면과 디스코드(자동완성, `/클리어` 메뉴, `/현황`)에 나오지 않아요. 저장된 값을 지우지는 않아서, 레벨이 오르면 다시 보여요.

### 추천은 이렇게 짜요: 친구로 꽉 찬 공대 우선 / 이번에 못 간 캐릭터 / 모두 편성

- 공대를 잘게 쪼개지 않고 **등록된 친구들끼리 최대한 꽉 채워서** 짜요. 공대마다 친구 캐릭터가 일정 수 이상(8인은 6명, 4인은 3명) 들어가야 공대를 만들어요. 그렇게 만들 공대가 하나도 없으면 기준을 8인 4명 / 4인 2명으로, 그래도 없으면 1명으로 낮춰서 추천이 비는 일은 없게 해요.
- 그다음 순서로 고르게 돼요: 편성되는 친구 캐릭터가 많은 것 → 외부 인원이 적은 것 → 외부 서포터가 적은 것 → 전투력 단계(여유/빠듯함/위험) → 숙련도 균형 → 공대끼리 전투력 평균 차이.
- 한 캐릭터는 한 번만 편성돼요. 외부인이 너무 많이 필요해서 이번 추천에서 뺀 캐릭터는 **이번에 못 간 캐릭터**로 따로 보여 줘요 (웹은 공대 아래, 디스코드는 추천 카드의 칸. 길면 `외 N개`).
- 추천 뒤에 **모두 편성**이 하나 더 붙을 수 있어요. 기준을 낮춰서 더 많은 캐릭터를 편성한 대안이고, "추천보다 외부 N명 더 필요 · 캐릭터 M개 더 편성"처럼 추천과 얼마나 다른지 적혀 있어요. 추천보다 더 많이 편성할 수 있을 때만 나와요. 디스코드에서 메시지가 너무 길어지면 모두 편성을 먼저 빼고 그 사실을 알려 줘요 (웹 화면에서는 늘 볼 수 있어요).

### 숙련도 (숙련 · 반숙 · 클경)

캐릭터마다, **레이드 이름마다** 정해요 (세르카 노말과 하드는 같은 숙련도). 정하지 않은 칸은 **반숙**으로 봐요.

- **숙련**: 여러 번 클리어해서 익숙해요 (●)
- **반숙**: 어느 정도 알아요, 기본값 (◐)
- **클경**: 클리어 경험만 있어요 (○)

정하는 곳: 웹의 캐릭터 카드(레이드 칩 옆 ⋯ 설정에서 숙련도 선택, 정하지 않은 칸은 "반숙 (기본)"으로 흐리게 보여요), 또는 디스코드 `/숙련도`. 원정대를 갱신하거나 주간 초기화가 지나도 그대로 남아요.

추천에 이렇게 반영돼요: 친구로 꽉 찬 공대, 외부 인원 수, 전투력 단계(여유/빠듯함/위험)를 먼저 보고, 그다음으로 ① 공대마다 숙련자가 최소 한 명 들어가게, ② 클경은 공대마다 한 명 이하로 나눠서, ③ 공대끼리 숙련도가 고르게 되도록 고른 뒤, 마지막으로 전투력 평균을 맞춰요. 전투력 단계 계산은 숙련도와 상관없어요. 외부 인원은 숙련도를 모르니 숙련자로 세지 않아요. 웹 추천 카드에는 공대마다 `숙련 1 · 반숙 1 · 클경 0` 요약이 붙어요. 그 레이드에 갈 캐릭터 중 **누군가 숙련도를 한 번이라도 정해 두었으면** 구성원마다 숙련도 배지가 붙고, 숙련자가 없는 공대에는 **⚠ 숙련자 없음** 표시가 나와요 (숙련자가 모자라면 막지 않고 표시만 해요). 아무도 정하지 않았으면 모두 기본값이라 경고는 나오지 않아요. 디스코드 추천도 같은 조건에서만 배지·요약·경고를 보여 줘요.

## 9. 문제 해결

- **Interactions Endpoint URL 저장 실패 / 서명 오류(401)**: `DISCORD_PUBLIC_KEY` 값이 앱의 Public Key와 같은지, 환경변수 수정 후 재배포했는지 확인해요.
- **"요청이 너무 많아요" (429)**: 로스트아크 API는 분당 요청 수 제한이 있어요(약 100회로 알려져 있어요). 1분 정도 기다린 뒤 다시 시도하세요. 원정대 한 번 등록에 캐릭터 수만큼 요청이 들어가요.
- **"캐릭터를 찾을 수 없어요"**: 대표 캐릭터 이름의 오타를 확인하세요. 캐릭터가 이름을 바꿨거나, 최근 접속하지 않은 경우에도 그럴 수 있어요.
- **"로스트아크 API 토큰이 올바르지 않아요"**: `LOSTARK_JWT`를 다시 복사해 넣고 재배포하세요.
- **전투력이 비어 있어요**: API가 전투력을 주지 않는 캐릭터가 있어요. 웹 화면에서 그 캐릭터의 전투력을 직접 입력하면 돼요. 입력한 값은 "수동"으로 표시되고 주간 갱신 뒤에도 유지돼요. 옆의 "자동 값으로"를 누르면 지워져요.
- **서포터/딜러가 잘못 표시돼요**: 웹 화면 클리어 표의 역할 배지를 누르면 그 캐릭터의 역할을 직접 바꿀 수 있어요("수동" 표시가 붙어요). 한 번 더 누르면 자동 판별로 돌아가요. 직접 정한 역할은 주간 갱신 뒤에도 유지돼요.
- **크론이 안 돌아요**: Vercel 프로젝트의 **Settings → Cron Jobs**(메뉴 이름은 바뀔 수 있어요)에서 등록 여부를 확인하세요. `CRON_SECRET` 환경변수가 없거나 다르면 `401`이 나와요. 크론은 배포된 프로덕션에서만 돌아요. 무료 플랜은 하루 1회 단위만 지원하는데, 이 설정은 주 1회라 괜찮아요. 크론이 실패해도 클리어 기록은 주차별로 따로 저장되기 때문에 새 주 기록은 자동으로 비어 시작해요.

## 10. 로아 API 확인 안내

로스트아크 API 응답 모양은 실제 토큰으로 한 번 확인했어요(2026-10-16). 원정대 조회에는 서버·캐릭터명·직업·아이템 레벨이 오고, 프로필 조회에는 전투력(`CombatPower`, 예: `"1,432.06"`)이 와요. 아이템 레벨이 레이드 최소 입장 레벨(1700)보다 낮은 캐릭터는 어떤 레이드에도 못 들어가므로 원정대 목록에서 아예 빼요(친구를 등록하거나 갱신할 때 적용돼요).

API가 바뀐 것 같을 때 다시 확인하는 방법이에요.

1. `.env.local`에 `LOSTARK_JWT`를 넣어요.
2. 실행해요. 토큰은 출력되지 않아요.

```
npx tsx scripts/probe-lostark.ts <대표캐릭터>
```

3. 출력된 필드(원정대 필드, 전투력 값)를 `tests/lostark/fixtures` 안의 파일들과 비교해요.
4. 다르면 fixtures와 `client.ts`의 파싱을 실제 응답에 맞게 고치고 `npm test`로 확인하세요.

서포터 판별 기준인 `SUPPORT_CLASSES`(`src/core/raids.ts`)는 홀리나이트, 도화가, 바드, 발키리 네 직업으로 확정되어 있어요(직업 이름으로 판별). 예외적인 캐릭터는 웹 화면에서 역할 배지를 눌러 직접 바꾸면 돼요.
